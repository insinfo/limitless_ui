Sincronização programática

Quando a tela carrega um registro antes das opções ou precisa limpar um select filho, use setSelectedItemByValue() e clearSelectedItem() com os flags de emissão desligados. Isso sincroniza a UI sem disparar ngModel, currentValueChange ou userValueChange.

currentValueChange x userValueChange

currentValueChange acompanha também mudanças programáticas do model. Use userValueChange quando a ação deve rodar somente após uma seleção feita pelo usuário.

Template de trigger

liSelectTrigger permite trocar o input visual por badge, chip ou botão compacto sem substituir a abertura do overlay, o foco, o estado disabled e os hooks de automação. Para controles internos como limpar seleção, chame ctx.clear($event) para evitar que o clique também alterne o overlay.

Busca opcional

A busca fica ligada por padrão porque o select costuma ser usado com listas longas. Quando a tela tem poucos itens e o programador controla esse tamanho, use [searchable]="false"; o overlay abre direto na lista de opções.

Validação declarativa

Para selects, a base declarativa fica em liRules, liMessages e liValidationMode. liType é exclusivo do li-input.

  • LiRule.required() cobre o caso mais comum de seleção obrigatória.
  • liMessages troca o texto do erro sem precisar controlar invalid manualmente.
  • liValidationMode="submitted" combina bem com liForm.validateAndFocusFirstInvalid().
